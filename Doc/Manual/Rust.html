This chapter describes SWIG's support of Rust. For more information on the Rust programming language, see rust-lang.org.

40.1 Overview

Rust can call C functions directly through its FFI (Foreign Function Interface) mechanism. However, there is no built-in way to call C++ code from Rust. SWIG fills this gap by generating safe Rust wrappers around C++ code.

SWIG's Rust module generates two layers of code:

  • FFI Layer: Low-level extern "C" declarations that directly interface with C/C++. This layer uses raw pointers and C-compatible types.
  • Safe Wrapper Layer: High-level Rust API with proper ownership semantics, type safety, and idiomatic Rust patterns.

The generated code is compatible with Rust 1.0 and later, with no external crate dependencies.

40.2 Examples

Working examples can be found in the SWIG source tree. Test cases are available in Examples/test-suite/rust.

40.3 Running SWIG with Rust

To generate Rust bindings, use the -rust option with SWIG: 

swig -rust -c++ -module example example.i

This will generate:

  • example_wrap.cxx - C++ wrapper functions
  • example.rs - Rust FFI declarations and safe wrappers

To compile and use the bindings, you need to: 

# 1. Set SWIG_LIB environment variable
export SWIG_LIB=/path/to/swig/Lib

# 2. Run SWIG
swig -rust -c++ -module example example.i

# 3. Compile C++ wrapper
g++ -c example_wrap.cxx -o example_wrap.o

# 4. Create static library
ar rcs libexample.a example_wrap.o

# 5. Use in Rust project
# Add to Cargo.toml:
# [dependencies]
# example = { path = "." }

40.3.1 Rust-specific Commandline Options

These are the command line options for SWIG's Rust module: 

swig -rust -help
Rust-specific options
-crate-name <name> Set the crate name (default: module name)
-module <name> Set the module name
-namespace <name> Generate wrappers into Rust mod <name>
-safe-wrapper Generate safe wrapper layer (default: on)
-ffi-only Only generate FFI declarations (no safe wrappers)
-no-directors Disable director (virtual function callback) support
-trait-overload Use trait-based overload resolution for more idiomatic Rust API
-director-thin Use thin vtable for directors (default, more efficient)
-director-boxed Use Box<Box<dyn Trait>> for directors (simpler)
-director-vtable Use associated const vtable for directors (zero overhead, default)

40.3.2 Generated Wrapper Files

SWIG generates the following files for Rust:

File Description
module_wrap.cxx C++ wrapper functions with extern "C" linkage
module_wrap.h C header file (only when directors are enabled)
module.rs Rust FFI declarations and safe wrapper layer

40.4 A tour of basic C/C++ wrapping

40.4.1 Rust Crate and Module Name

By default, the crate name and module name are derived from the %module directive: 

%module mymodule

This generates mymodule.rs. You can override these with command line options: 

swig -rust -c++ -crate-name mycrate -module mymodule example.i

40.4.2 Rust Names

SWIG translates C/C++ names to Rust names following these rules:

  • Function and method names are converted to snake_case
  • Class names become PascalCase struct names
  • Constants become SCREAMING_SNAKE_CASE
  • Enum names become PascalCase

40.4.3 Rust Constants

C/C++ constants are mapped to Rust const declarations: 

// C++
#define MAX_SIZE 100
const double PI = 3.14159;

Generates: 

// Rust
pub const MAX_SIZE: i32 = 100;
pub const PI: f64 = 3.14159;

40.4.4 Rust Enumerations

C/C++ enums are mapped to Rust enums with #[repr(C)]: 

// C++
enum Color { RED, GREEN, BLUE };

Generates: 

// Rust
#[repr(C)]
#[derive(Debug, Copy, Clone, PartialEq, Eq)]
pub enum Color {
    RED = 0,
    GREEN = 1,
    BLUE = 2,
}

40.4.5 Rust Classes

C++ classes are mapped to Rust using the struct + trait + impl pattern: 

// C++
class Animal {
public:
    Animal(const std::string& name);
    virtual ~Animal();
    virtual void speak();
    std::string getName() const;
private:
    std::string name;
};

Generates: 

// Rust

// Struct holding the C++ pointer
pub struct Animal {
    ptr: *mut c_void,
}

// Trait defining the interface
pub trait AnimalTrait {
    fn speak(&mut self);
    fn getName(&self) -> String;
}

// Implementation
impl Animal {
    pub fn new(name: &str) -> Self {
        // ...
    }
}

impl Drop for Animal {
    fn drop(&mut self) {
        // Call C++ destructor
    }
}

impl AnimalTrait for Animal {
    fn speak(&mut self) {
        unsafe { ffi::Animal_speak(self.ptr) }
    }
    fn getName(&self) -> String {
        // ...
    }
}

40.4.5.1 Rust Class Memory Management

Memory management follows Rust's ownership model:

  • Constructors create a new Rust struct that owns the C++ object
  • Drop is implemented to call the C++ destructor when the Rust struct goes out of scope
  • No Copy/Clone by default - prevents accidental double-frees

For C++ classes that are safe to copy, you can implement Copy/Clone manually or use typemaps.

40.4.5.2 Rust Class Inheritance

Single inheritance is supported: 

// C++
class Dog : public Animal {
public:
    Dog(const std::string& name);
    void speak() override;
};

The generated Rust code includes the base class trait: 

// Rust
pub trait DogTrait: AnimalTrait {
    fn speak(&mut self);
}

Multiple inheritance is partially supported - additional base classes use upcast functions.

40.4.6 Rust Director Classes

Directors allow Rust to override C++ virtual functions. This enables implementing C++ interfaces in Rust and passing them back to C++.

40.4.6.1 Director Example

Enable directors in your interface file: 

// SWIG interface
%module(directors="1") example
%feature("director") Callback;

%inline %{
class Callback {
public:
    virtual ~Callback() {}
    virtual void onEvent(int id) {}
    virtual int process(int value) { return value; }
};

class Processor {
public:
    void setCallback(Callback* cb) { callback = cb; }
    void notify(int id) { if (callback) callback->onEvent(id); }
private:
    Callback* callback = nullptr;
};
%}

In Rust, implement the director trait: 

// Rust

// Define your callback implementation
struct MyCallback;

impl CallbackDirector for MyCallback {
    fn onEvent_int(&self, id: i32) {
        println!("Event received: {}", id);
    }
    
    fn process_int(&self, value: i32) -> Option<i32> {
        Some(value * 2)  // Double the value
    }
}

// Use it
fn main() {
    let callback = Callback::new_with_trait(MyCallback);
    let processor = Processor::new();
    processor.setCallback(callback.ptr_mut());
    processor.notify(42);
}

40.4.6.2 Director Safety

Re-entrancy Warning: C++ may call back into Rust during method execution. To ensure safety:

  • Director trait methods use &self by default (not &mut self)
  • Use Cell<T> for simple mutable state (Copy types)
  • Use RefCell<T> for complex state (panics on re-entrancy)
  • If you're certain no re-entrancy will occur, use &mut self with caution
// Safe: uses Cell for mutable state
struct SafeCallback {
    count: Cell<i32>,
}

impl CallbackDirector for SafeCallback {
    fn onEvent_int(&self, id: i32) {
        self.count.set(self.count.get() + 1);
    }
}

40.4.7 Function Overloading

Since Rust doesn't support function overloading, SWIG uses one of two approaches:

1. Type Suffix (default): 

// C++
void draw(int x, int y);
void draw(Point p);

// Rust
obj.draw_int_int(x, y);
obj.draw_Point(p);

2. Trait-based Overloading (with -trait-overload): 

// Rust
pub trait Draw {
    type Output;
    fn call(self, obj: &mut Shape) -> Self::Output;
}

impl Draw for (i32, i32) { /* ... */ }
impl Draw for Point { /* ... */ }

// Usage
shape.draw((10, 20));  // Calls draw(int, int)
shape.draw(Point { x: 10, y: 20 });  // Calls draw(Point)

40.4.8 Rust Templates

C++ template instantiation via %template is supported: 

// C++
template<typename T>
class Container {
public:
    void add(const T& item);
    T get(int index) const;
};

// SWIG interface
%template(IntContainer) Container<int>;
%template(StringContainer) Container<std::string>;

Generates: 

// Rust
pub struct IntContainer { ptr: *mut c_void }
pub struct StringContainer { ptr: *mut c_void }

impl IntContainer {
    pub fn add(&mut self, item: i32);
    pub fn get(&self, index: i32) -> i32;
}

40.4.9 Namespaces

C++ namespaces are mapped to Rust modules: 

// C++
namespace graphics {
    class Shape { /* ... */ };
    namespace primitives {
        class Circle : public Shape { /* ... */ };
    }
}

Generates: 

// Rust
pub mod graphics {
    pub struct Shape { /* ... */ }
    
    pub mod primitives {
        pub struct Circle { /* ... */ }
    }
}

40.4.10 Rust and C++ Exceptions

C++ exceptions cannot be caught across the FFI boundary. SWIG provides mechanisms to convert exceptions to Rust-friendly error handling:

  • Panic: Default behavior - C++ exceptions cause panic!
  • Error codes: Use typemaps to convert exceptions to Result<T, E>

Include the exception handling library: 

%include "exception.i"

40.4.11 Smart Pointers

SWIG provides support for C++ smart pointers: 

// SWIG interface
%include "std_shared_ptr.i"

%shared_ptr(MyClass)

%inline %{
class MyClass {
public:
    void method();
};
%}

In Rust, smart pointers are represented as opaque handles: 

// Rust
pub struct MyClassSharedPtr {
    ptr: *mut c_void,
}

40.4.13 Rust Typemaps

SWIG typemaps allow you to customize type conversion. Rust-specific typemaps:

Typemap Description
rusttype Rust type visible to user (e.g., i32, String)
rsffitype Rust FFI type (e.g., c_int, *const c_char)
rsin Rust to C conversion code for input parameters
rsout C to Rust conversion code for return values
rscheck Type checking code for overloaded functions

Example custom typemap: 

// SWIG interface
%typemap(rusttype) std::string "String"
%typemap(rsffitype) std::string "*const c_char"
%typemap(rsin) std::string {
    $1 = $input.as_ptr() as *const c_char;
}
%typemap(rsout) std::string {
    $result = CStr::from_ptr($1).to_string_lossy().into_owned();
}

SWIG automatically maps C++ operator overloads to Rust standard library traits. This allows using familiar Rust syntax for operations on wrapped C++ classes.

Supported Operator Mappings:

operator%std::ops::Rema % b
operator==std::cmp::PartialEqa == b
operator!=std::cmp::PartialEqa != b

operator>std::cmp::PartialOrda > b
operator>=std::cmp::PartialOrda >= b

Example: 

// C++
class Vector2 {
public:
    Vector2(double x, double y);
    Vector2 operator+(const Vector2& rhs) const;
    Vector2 operator*(double scalar) const;
    bool operator==(const Vector2& rhs) const;
    double operator[](int index) const;
};

Generates Rust code that allows: 

// Rust
let v1 = Vector2::new(1.0, 2.0);
let v2 = Vector2::new(3.0, 4.0);

let sum = v1.op_add(&v2);      // Vector2 operator+
let scaled = v1.op_deref(2.0);  // Vector2 * scalar
let eq = v1.op_eq(&v2);         // bool equality
let x = v1.op_index(0);         // index access

Note: Use %rename_operators macro to rename operators to valid Rust names (e.g., operator+ becomes op_add).

40.4.15 STL Container Types

SWIG provides bindings for C++ STL containers, mapping them to equivalent Rust types:

C++ Type Rust Type Include File
std::vector<T>Vec<T>std_vector.i
std::deque<T>VecDeque<T>std_deque.i
std::list<T>LinkedList<T>std_list.i
std::map<K,V>BTreeMap<K,V>std_map.i
std::set<T>BTreeSet<T>std_set.i
std::unordered_map<K,V>HashMap<K,V>std_unordered_map.i
std::unordered_set<T>HashSet<T>std_unordered_set.i
std::pair<T,U>(T, U)std_pair.i
std::stringStringstd_string.i

Example with std::vector: 

// SWIG interface
%include "std_vector.i"

%template(IntVector) std::vector<int>;
RUST_VECTOR_TRAITS(int, IntVector)

%inline %{
std::vector<int> createVector() {
    return {1, 2, 3, 4, 5};
}
%}

Rust usage: 

// Rust
let vec = createVector();
println!("Length: {}", vec.len());
println!("First: {}", vec.getitem(0));

// Convert to Rust Vec
let rust_vec: Vec<i32> = vec.to_vec();

// Create from Rust Vec
let from_rust = IntVector::from_vec(vec![1, 2, 3]);

std::unordered_map Example: 

// SWIG interface
%include "std_unordered_map.i"

%template(StringIntMap) std::unordered_map<std::string, int>;
RUST_UNORDERED_MAP_TRAITS(std::string, int, StringIntMap)

Helper Macros:

  • RUST_VECTOR_TRAITS(CType, Name) - Generate Vec conversion traits
  • RUST_DEQUE_TRAITS(CType, Name) - Generate VecDeque conversion traits
  • RUST_LIST_TRAITS(CType, Name) - Generate LinkedList conversion traits
  • RUST_MAP_TRAITS(KType, VType, Name) - Generate BTreeMap conversion traits
  • RUST_SET_TRAITS(CType, Name) - Generate BTreeSet conversion traits
  • RUST_UNORDERED_MAP_TRAITS(KType, VType, Name) - Generate HashMap conversion traits
  • RUST_UNORDERED_SET_TRAITS(CType, Name) - Generate HashSet conversion traits

40.5 Advanced Topics

40.5.1 Pragma Directives

SWIG pragmas for Rust: 

%pragma(rust) module_code="fn helper() { }"
%pragma(rust) module_import="use std::collections::HashMap;"

40.5.2 Feature Flags

Feature flags control code generation: 

// Disable wrapping for a method
%feature("ignore") MyClass::internalMethod;

// Mark a class as having director support
%feature("director") MyCallback;

// Generate only FFI (no safe wrapper)
%feature("ffi-only") MyClass::lowLevelMethod;

40.5.3 Thread Safety

The generated Rust wrappers are thread-safe for read-only operations. However:

  • Mutable operations (&mut self) require exclusive access
  • C++ code must be thread-safe for concurrent calls
  • Director callbacks can be called from any C++ thread
